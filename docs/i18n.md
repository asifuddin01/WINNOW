# Languages in Winnow

Winnow's interface text comes from catalogues read by [i18next](https://www.i18next.com/)
(guide section 14). English is the only language so far. The setup is laid out so
Bangla (বাংলা), the first planned language, or any other can be added as a folder of JSON
files.

## How it fits together

| Piece | Where |
| --- | --- |
| Setup: languages, the language chosen, the fallback | `frontend/src/i18n/index.ts` |
| The English catalogue | `frontend/src/i18n/locales/en/common.json` |
| Typed keys (a misspelt key fails `pnpm typecheck`) | `frontend/src/i18n/i18next.d.ts` |
| Tests: every key resolves, plurals, numbers | `frontend/src/i18n/i18n.test.ts` |

- **Components** call `const { t } = useTranslation();` and write `t("nav.screen")`.
- **Plain modules** (no React) use `i18n.t` from `@/i18n`. An example is
  `features/notifications/wording.ts`.
- **Values** are written `{{name}}`. React escapes what it renders, so the catalogue
  holds plain text and never HTML.
- **Plurals** use the `_one` and `_other` suffixes (`palette.count_one`,
  `palette.count_other`), and the call passes `count`. Languages with more forms add
  their own suffixes, such as `_few` and `_many`. i18next picks the right form from
  `Intl.PluralRules`.
- **Numbers inside sentences** are written `{{count, number}}`, which formats them with
  `Intl.NumberFormat` in the chosen language: 1,500 in English, ১,৫০০ in Bangla.
- **Dates and times** (`lib/format.ts` and the pages) are formatted with `Intl` in the
  browser's own locale.

The language is the first of the browser's preferred languages that Winnow speaks, else
English. The `<html lang>` attribute follows it, so screen readers pronounce the page
correctly. With only one language there is no switcher: a menu with one option would
be noise.

## Adding a language (Bangla as the example)

1. Copy `locales/en/common.json` to `locales/bn/common.json` and translate the values.
   Keep the keys and the `{{placeholders}}`. A missing key falls back to English, so a
   partial catalogue still works.
2. In `i18n/index.ts`:
   - Add the language to `LANGUAGES`: `{ en: "English", bn: "বাংলা" }`.
   - Add its catalogue to `resources`.

   Only English needs to be bundled up front. Other languages can be loaded when chosen
   (`i18next-resources-to-backend` with a dynamic `import()`), which keeps them out of
   the initial bundle and inside its 200 KB budget.
3. Add a language menu next to the colour theme once there are two languages. Store the
   choice the way the theme is stored, and pass `i18n.language` to the `Intl`
   formatters in `lib/format.ts`, so that dates follow the menu rather than only the
   browser.
4. Check the pages in the new language at phone width: Bangla words and labels run
   longer than English ones.

## What is translated so far

The app shell, which appears on every page:

- The sidebar (every navigation link), the top bar and the skip link.
- The command palette: pages, actions, groups and the result count.
- The notification bell and the wording of every notice.
- The colour-theme and account menus.
- The offline and email-confirmation banners.
- The error page and the not-found page.

The pages (screening, import, records, report, settings, account, admin) still have
their English text inline. They move to the catalogue page by page, one namespace each
(`screening.json`, `import.json`, and so on), when each page is next changed. Until
then, adding a language translates the shell only. When moving a page, keep the English
text identical, so its tests keep passing unchanged.
